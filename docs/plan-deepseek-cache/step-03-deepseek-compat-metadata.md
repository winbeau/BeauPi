# Step 3 — DeepSeek compat 元数据修正

## 目标

DeepSeek 的 `supportsLongCacheRetention` 显式为 `false`，避免 `cacheRetention: "long"` 时向 DeepSeek 发送未验证支持的 `prompt_cache_key` / `prompt_cache_retention: "24h"`。默认 `short` 行为不变。

## 背景事实（已核实）

- `packages/ai/src/api/openai-completions.ts:1466-1473` `detectCompat`：
  `supportsLongCacheRetention: !(isTogether || isCloudflareWorkersAI || isCloudflareAiGateway || isNvidia || isAntLing)`——**排除名单不含 DeepSeek**，因此 DeepSeek 当前默认 `true`。
- `buildParams`（L689-694）：`cacheRetention === "long" && supportsLongCacheRetention` 时发送 `prompt_cache_key`（=sessionId，64 字符钳制）和 `prompt_cache_retention: "24h"`。DeepSeek 官方 API 无此参数，可能被拒或忽略。
- `packages/ai/src/providers/data/deepseek.json` 是生成产物（`deepseek.models.ts` 头部注明 auto-generated by `scripts/generate-models.ts`）。**不要直接改 JSON**；改生成器，运行时生效靠 `detectCompat`（当前 JSON 里没有该字段，`getCompat` 回落到运行时检测值）。

## 文件变更

### 1. `packages/ai/src/api/openai-completions.ts`

`detectCompat` 的排除名单加 `isDeepSeek`：

```ts
supportsLongCacheRetention: !(
	isDeepSeek ||
	isTogether ||
	isCloudflareWorkersAI ||
	isCloudflareAiGateway ||
	isNvidia ||
	isAntLing
),
```

### 2. `packages/ai/scripts/generate-models.ts`

同一处排除名单（约 L622-628，`openAICompletionsCompat` 计算函数内）加 `isDeepSeek ||`，保证下次重新生成 catalog 时 `deepseek.json` 写入 `"supportsLongCacheRetention": false` 与运行时一致。

**重新生成是可选动作**：`npm --prefix packages/ai run generate-models` 可能需要网络（models.dev）。运行时行为由第 1 处改动立即生效；生成器改动只是保持未来一致性。若选择重新生成，按 AGENTS.md 允许把连带产生的 `models.generated.ts` diff 一起提交。

## 测试

追加到 `packages/ai/test/openai-completions-prompt-cache.test.ts`（复用其 `captureRequest`）：

1. `deepseek long retention sends no prompt_cache_key`：`getModel("deepseek","deepseek-v4-flash")` + `cacheRetention: "long"` → payload 无 `prompt_cache_key`、无 `prompt_cache_retention`。
2. `deepseek default short retention unchanged`：默认 → 无 `prompt_cache_key`（与 step-01 用例 4 一致，此处防回归）。
3. `openai long retention still sends key`：`gpt-4o-mini` + long → 仍发送（证明只影响 DeepSeek）。
